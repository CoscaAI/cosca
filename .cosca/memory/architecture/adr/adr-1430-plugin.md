# ADR-1430: Create Plugin Chief

**Status**: Accepted
**Deciders**: Chief AI Platform Architect
**Date**: 2026-07-23
**Tags**: organization, chief, v3.0, enterprise

## Context
The Cosca framework needed to expand its organizational coverage to include enterprise domains that were previously uncovered or inadequately covered by existing chiefs.

## Decision
Create the Plugin Chief role as a first-class department in the Cosca organizational structure, with dedicated SKILL.md, specialists, and council representation.

## Rationale
Plugin extensibility is critical for platform adoption. Previously no ownership for plugin architecture, SDK, registry, or lifecycle. A dedicated Plugin Chief enables third-party extensions and marketplace ecosystem.

## Alternatives Considered
1. Extend Platform Chief scope: Overloaded. 2. Community-managed plugins: Lacks governance and security. 3. Dedicated Plugin Chief: Correct for ecosystem growth.

## Decision Outcome
Create dedicated Plugin Chief with:
- Reports to: as defined in ORGCHART.md
- Specialists: as defined in departments/plugin/SKILL.md
- Council representation: as defined in COUNCILS.md

## Consequences
- Clear ownership for the domain
- Dedicated focus and accountability
- Better cross-department coordination through council representation
- Increased framework size (14 new departments)

## Compliance
- All new departments follow CONVENTIONS.md format
- All departments have AGENT_DNA.md-compliant contracts
- All departments have council representation
