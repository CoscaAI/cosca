Padrão arquitetural extraído do repositório MIT "Osiris" (github.com/simplifaisoul/osiris), arquivo src/lib/sourceCache.ts — mineração manual 2026-09-04, avaliado junto ao Don. FRENTE 2.

CARGA DE FONTE RESILIENTE (single-flight + TTL + stale-on-error):
Padrão de cache de fonte upstream com 4 comportamentos combinados:
1) TTL — serve da memória até expirar (evita re-download de índice que muda raramente; no osiris um índice de ~500KB re-baixado a cada request era desperdício; fontes lentas dominavam a resposta, ex. MDOT ~7s, NZTA ~8s).
2) DEDUPE SINGLE-FLIGHT — N acessos concorrentes ao MESMO cache-miss compartilham UMA única requisição upstream (não esmagam a fonte; um fan-out `region=all` bate em todas as fontes ao mesmo tempo).
3) STALE-ON-ERROR — se o refresh falha, serve o último dado bom ('stale') em vez de zerar a camada; resultado vazio também conta como refresh falho (mantém o que tinha); re-tenta mais cedo que o TTL cheio (ex. +60s) mas não martela o upstream.
4) MAPA COM TETO — limite de entradas (ex. 500); evicta a mais antiga (Map preserva ordem de inserção); NUNCA evicta uma entrada com request in-flight.

POR QUE É VALIOSO: elimina thundering herd (efeito manada); segura a fonte quando ela pisca; não deixa o sistema ficar 'cego' por uma falha transitória. Oposto de transformar falha transitória em amnésia artificial. Resoância direta com memória/conhecimento do COSCA (não apagar conhecimento por um refresh que caiu; servir stale + marcar degraded).

CAPOS: cache chief + memory chief (implementação). ADR-039.
