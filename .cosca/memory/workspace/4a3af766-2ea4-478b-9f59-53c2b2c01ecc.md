POLITICA DE EXECUCAO DE TOOLS (Tool Execution Policy) - do professor, 2026-08-30. Filosofia central: rigoroso para SEGURANCA, tolerante para EXECUCAO RECUPERAVEL. Nao afrouxar o rigor - torna-lo OBSERVAVEL, RECUPERAVEL e PROPORCIONAL ao tipo de falha. REGRA DE OURO: nenhuma tool pode prender Kernel/agente/sessao indefinidamente. CICLO DE VIDA: REQUEST -> CAPABILITY CHECK (DENY se nao tem) -> SCHEMA VALIDATION (REJECT se invalido) -> POLICY/PERMISSION (DENY se proibido) -> EXECUTION (transient=RETRY, timeout=ABORT+RECOVER, permanent=FAIL) -> RESULT VALIDATION (invalido=RECOVER/FAIL) -> TOOL_RESULT -> ORCHESTRATOR. TAXONOMIA de falha: FailureInvalidArguments, FailureCapability, FailurePermission, FailureNotFound, FailureTimeout, FailureUnavailable, FailureTransient, FailureExecution, FailureInvalidResult, FailureInternal. Cada classe tem comportamento: se faz retry, se bloqueia agente, estrategia de recuperacao (ex: permission NAO se retry; connection reset SI retry). TIMEOUT em 3 niveis: Tool (ex 30s) < Agent (ex 10min) < Task (ex 30min). RETRY politico (MaxAttempts + Backoff), nunca infinito, nao retry de permission. AGENTE recebe ERRO OPERACIONAL estruturado (status/tool/failure_class/retryable/attempt/duration_ms/message/recovery), nao "tool failed" generico. Tool CANCELAVEL via context.Context (select {ctx.Done / result}). ESTADO EXPLICITO: PENDING->VALIDATING->AUTHORIZED->RUNNING->{SUCCESS|RETRYING|TIMEOUT->RECOVERING|FAILED->RECOVERING}. TRACE OBRIGATORIO: TOOL_REQUESTED/TOOL_VALIDATING/TOOL_AUTHORIZED/TOOL_STARTED/TOOL_RETRY/TOOL_TIMEOUT/TOOL_FAILED/TOOL_SUCCEEDED/TOOL_CANCELLED/TOOL_RECOVERED com trace_id/task_id/agent_id/tool_id/attempt/timestamp/duration/failure_class. NAO confundir erro de AGENTE com erro de TOOL (tool falhou != agente falhou). ORCHESTRATOR decide recuperacao (retry/fallback/delegate/continue/abort), nao a tool. Agente NUNCA contorna capability/permission (CAPABILITY_MISSING -> report -> orchestrator -> delegate). Conectar ao ADR-031 (Task->Agent->Tools->Tokens->UsefulWork->Failures->Retries) e ao Auto-Audit (enxergar padrao: timeout rate por tool, agent failure profile).
