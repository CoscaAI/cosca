Padrão arquitetural extraído do repositório MIT "Osiris" (github.com/simplifaisoul/osiris), arquivo src/lib/ssrf-guard.ts — mineração manual 2026-09-04, avaliado junto ao Don. FRENTE 4. (AUGMENT do guard já existente no COSCA, não padrão novo.)

HARDENING SSRF (defesa em 2 camadas + revalidação hop-by-hop):
1) CANONICALIZAÇÃO DE IP: rejeitar formas NÃO-canônicas de IPv4 — decimal (2130706433), hex (0x7f.0.0.1), octal (0177.0.0.1), notação mista/curta. Só aceita dotted-quad estrito. Defesa contra IP-confusion (atacante burla com forma alternativa que o kernel resolve).
2) REJEITAR IPv6 em ranges reservados: :: , ::1 , ::ffff: (IPv4-mapped), 64:ff9b:: NAT64, 100:: discard, 2001:db8: doc, fc/fd unique-local, fe8-feb link-local, fec-fef site-local, ff multicast.
3) BLOCKS IPv4: 0.0.0.0/8, 10/8, 100.64/10 (CGNAT/Tailscale), 127/8, 169.254/16 (incl. metadata 169.254.169.254), 172.16/12, 192.0.0/24, 192.0.2/24 TEST-NET-1, 192.168/16, 198.18/15, 198.51.100/24 TEST-NET-2, 203.0.113/24 TEST-NET-3, 224/4 multicast, 240/4 reserved.
4) BLOCKLIST DE HOSTNAMES METADATA: localhost, *.localhost, host.docker.internal, *.local, *.internal, metadata.google.internal (bloqueados ANTES do DNS, independente do IP final).
5) REVALIDAÇÃO HOP-BY-HOP DE REDIRECT: safeFetch segue redirects MANUALMENTE, re-validando o host de cada hop; bloqueia redirect para host privado vindo de um público aparente; só permite http/https; teto de maxRedirects. TOCTOU: defesa total exigiria IP pinning no socket, mas rejeitar no lookup bloqueia ataque não-rebinding.
6) RATE LIMITER POR-IP + getClientIp (x-forwarded-for/x-real-ip).

NOTA DE CONTEXTO: o COSCA JÁ tem guard anti-SSRF (cosca_cosca_web 'SSRF guard' host resolvido + IP público validado). FRENTE 4 = ABRIR DIFF com o guard atual e portar o que FALTA (rejeição de IPv4 não-canônico, revalidação por hop de redirect, blocklist de metadata, cobertura IPv6).

POR QUE É VALIOSO: SSRF não é só 'URL inicial segura'; é URL inicial→DNS→IP→redirect→DNS→IP→destino final, cada hop re-obedecendo ao guard. Fecha gaps de IP-confusion e redirect-to-private.
