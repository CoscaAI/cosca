| **Learned** | **(1) OLLAMA NÃO SOBREVIVE A REBOOT SEM SYSTEMD SERVICE: o ollama rodava manualmente (`OLLAMA_HOST=127.0.0.1:11435 ollama serve &`) sem unit file — quando o processo morre (OOM, crash, reboot), ninguém levanta. O serve starta depois (tem dependência implícita) e sobrescreve. Isso viola o Single Owner Model (L154). Fix manual resolve o sintoma; fix de raiz exige alterar o serve para escrever em `.cosca/serve.pid` separado ou não escrever PID file (systemd já trackeia via MainPID).** **(4) cosca-voice.service foi removido do systemd (unit file deletado) mas o script `voice_conversation.py` continuava intacto em `scripts/voice/`.
