## L290 — 2026-08-16 — Crash-loop do serve ao assinar a chain: a janela commit→sign | Level 4

| Field | Value |
|-------|-------|
| **Agent** | cosca-kernel |
| **Task** | Durante a criação do CARRO_PROTOCOL, descobriu-se que o serve entra em crash-loop (exit 1) TODA vez que a family chain é assinada. Reproduzido 2x: sign do L288 → 7 restarts; sign do L289 → 8 restarts. |
| **Technique** | Level 4 — **(1)** Reprodução determinística: cada `cosca-check --sign-auto` com o serve rodando causava ~7-8 restarts (NRestarts 0→7→15), sempre status=1. **(2)** Causa raiz por leitura de código: `bootstrap.Compose` (bootstrap.go:173-192) roda `integrity.Check(coscaRoot)` NO BOOT — fail-closed, "family chain breach detected — startup blocked" → `logger.Fatal` → exit 1. **(3)** Mecanismo: a ORDEM SAGRADA (L199, commit ANTES de signar) cria uma JANELA onde o git commit hash é NOVO mas a `family_chain.dat` ainda é VELHA (manifest antigo). Durante o sign (leitura de 1641 arquivos + reescrita dos 94MB), o serve que reinicia lê a chain inconsistente → breach → bloqueia. Assim que o sign termina, a chain fica consistente e o serve sobe limpo. |
| **Level** | 4 |
| **Outcome** | success — causa raiz identificada com precisão (bootstrap.go → integrity.Check fail-closed), workaround documentado no CARRO_PROTOCOL §6.7. |
| **Confidence** | 0.93 (validado: reproduzido 2x com contagem de restarts exata, mecanismo lido diretamente no código bootstrap.go) |

| **Learned** | **(1) A janela commit→sign É um estado "chain quebrada" legítimo: entre o commit e o sign, o git commit hash ≠ âncora da family_chain.dat — o serve corretamente bloqueia (fail-closed), mas isso vira crash-loop se o Restart=always estiver ligado e o sign demorar.** **(2) O trabalho de assinar é pesado (1641 arquivos + 94MB) — a janela dura segundos, não milissegundos; por isso o loop é de 7-8 restarts, não 1.** **(3) Workaround limpo: `systemctl --user stop cosca-serve` → commit → sign → `start` — zero loop.** **(4) O comportamento é CORRETO (não é bug de segurança), é um gotcha operacional: fail-closed + restart automático = loop transitório que self-heal.** |
