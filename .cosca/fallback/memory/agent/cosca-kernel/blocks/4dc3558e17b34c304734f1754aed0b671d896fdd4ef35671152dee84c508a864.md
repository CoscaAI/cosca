| **Learned** | O Professor reforçou a regra de processo: quando um agente está EXECUTANDO uma rodada, não empurrar novas ideias — deixa-lo terminar, medir e mostrar o que realmente conseguiu. O "menino quebrando a cabeça" (agente investigando/falhando/corrigindo) é SINAL BOM do ciclo certo: problema→investigação→hipótese→implementação→teste→benchmark→(falha? isola→entende→corrige | ok? registra→otimiza). Quando o resultado chega, CLASSIFICAR: 🟢 já funciona · 🟡 funciona mas precisa otimizar · 🔴 arquitetura precisa mudar · 🚀 oportunidade nova descoberta pelo próprio Cosca. Isso se conecta ao L304 (recovery loop) e ao L305 (adaptive runtime): o ciclo de adaptação fechado só funciona se não for interrompido a cada iteração. Interromper para dar ideia nova = matar o benchmark antes da medição = matar o aprendizado (P13: sem medição não há fato). |
