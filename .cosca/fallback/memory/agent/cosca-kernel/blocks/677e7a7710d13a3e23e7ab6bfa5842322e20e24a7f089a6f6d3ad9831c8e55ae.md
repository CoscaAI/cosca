| **Learned** | **(1) O double-loop (status + operations) é o padrão que falta na nossa esteira.** Separar detecção de drift (status loop, rápido) de execução de passos (operation loop, lento) permite: status sempre fresco, operações longas sem bloquear, checkpoint para retomar após crash. **(2) O three-tier diff strategy mostra que diff não é uma função única — é uma cascata de precisão.** Server-side diff é o mais preciso mas requer API call; three-way diff é o fallback; two-way é o último recurso. A normalização pré-diff é crucial: sem ela, falsos positivos explodem. **(3) Phased+Waved sync com dry-run gate é superior ao nosso StepRunner linear.** Fases (PreSync/Sync/PostSync) + waves (ordenadas por annotation) + dry-run prévio garantem: hooks, ordem controlada, validação sem efeitos colaterais. A máquina de estados iterativa (`SyncContext.Sync()` chamada repetidamente) permite checkpoint entre steps. **(4) Health assessment com múltiplos status + Lua scripts é o modelo para nossos agentes.** Não basta "funciona/não funciona" — precisamos de Healthy/Progressing/Degraded/Missing, com scripts customizados por tipo de agente. A agregação "pior status vence" é simples e eficaz. **(5) O modelo generator+template é superior aos nossos 5 templates fixos do TaskPlanner.** Separar descoberta (Generator) de renderização (Template) permite compor via Matrix/Merge. Aplicável a: geração de workflows, agentes, configurações. **(6) O padrão de resource ownership via stamping (tracking-id) resolve rastreabilidade de artefatos.** Cada learning/pattern/output teria stamp com agente+workflow que o gerou — audit trail completo. **(7) O modelo trigger/template/service de notificações é o que precisamos para sair do console-only.** Triggers avaliam condições (task completou, health degraded), templates renderizam por canal (Telegram, webhook), services entregam. Dedup via `oncePer` evita spam. |
