| **Learned** | **(1) A verificação já era 100% Go nativa — o gap era só a assinatura.** `internal/integrity/integrity.go` (405 linhas) já usava `crypto/ed25519` para verificar. Mas o `VerifyOrFatal()` mandava rodar `python3 .cosca/keys/audit_trail.py` — e o módulo importado (`/tmp/cosca_family_chain.py`) não existia mais. **(2) A convenção de assinatura é não-canônica mas funciona: Ed25519 sobre o HEX STRING do SHA-256, não sobre o hash binário nem sobre o conteúdo direto.** O Python fazia `private_key.sign(sha256_str(content).encode())` — o Go replica exatamente. Motivo: o Python `cryptography` library espera bytes, e passar o hex string produz um "message" de 64 bytes que o Ed25519 assina sem problemas. **(3) Chains multi-bloco exigem verificação seletiva: TODOS os blocos têm assinatura verificada (prova de integridade da chain), mas só o ÚLTIMO bloco tem hashes conferidos contra o disco (estado atual).** Antes, o `Check()` verificava arquivos de todos os blocos → falso positivo garantido se o arquivo mudou entre blocos. **(4) PKCS#8 PEM é o formato canônico para Ed25519 private keys: `x509.MarshalPKCS8PrivateKey()` + `pem.EncodeToMemory()` produz o mesmo formato do Python `cryptography`. SPKI PEM para public key: `x509.MarshalPKIXPublicKey()`. A chave privada do Python (gerada com `cryptography`) carrega perfeitamente no Go via `x509.ParsePKCS8PrivateKey()`.** **(5) O formato do bloco: `======= BLOCK N =======` como separador, header com `# Hash/Time/Files`, depois `SIGNATURE/SIGNER` (fora do conteúdo assinado), depois `PREV/TIME/FILES/MANIFEST_HASH/---/manifest` (conteúdo assinado). A assinatura cobre do PREV até o fim do JSON, trimmed de trailing newlines. O `MANIFEST_HASH` permite verificação rápida do manifest sem parse do JSON.** **(6) `filepath.Walk` + `sort.Slice` por path garante manifest determinístico — mesma ordem em qualquer SO. Crítico para que o hash do manifest seja reproduzível. |
