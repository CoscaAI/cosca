| **Learned** | **(1) O padrão SharedInformer+Lister+Workqueue é a base de TODO controller Kubernetes — e nossa arquitetura de agentes é o oposto.** Agentes chamam APIs diretamente, sem cache, sem fila. Adotar esse padrão significaria: cache local do knowledge.db para leituras instantâneas, watch para eventos de mudança, workqueue para processamento assíncrono com rate-limiting. **(2) A separação spec/status + reconciliation loop é o modelo declarativo canônico.** Nossos workflows já seguem isso implicitamente (Don→agente→kernel), mas sem formalização. Formalizar como WorkflowSpec/WorkflowStatus daria reconciliação contínua até convergência. **(3) Interface segregation by capability é superior ao nosso modelo de agentes monolíticos.** Em vez de uma interface `Agent` com 20 métodos, agentes implementariam `TaskRunner`, `HealthChecker`, `StatusReporter` como interfaces granulares. O kernel descobre capabilities via type assertion em runtime. **(4) O scheduler framework com 10+ extension points é o modelo para nosso workflow engine.** Cada fase do workflow (validate, build, test, deploy, notify) seria um extension point onde plugins registram comportamento. CycleState carrega estado entre fases. Framework chama plugins em ordem. **(5) GuaranteedUpdate com Preconditions{ResourceVersion} é o padrão de consistência sem locks.** Nossas engines compartilhadas precisam disso — em vez de mutex, optimistic concurrency com retry loop. **(6) Watch + Bookmark é o modelo de streaming de eventos que falta.** watch.Interface com channel + Bookmark para reconexão eficiente permitiria: agentes reagirem a mudanças no knowledge.db em tempo real, dashboard com SSE/WebSocket, workflows orientados a eventos. **(7) CRD mostra como extensibilidade sem recompilar funciona.** Definir novos tipos de agente/skill como YAML com schema validation, sem tocar no binário. **(8) StatusError + Is* predicates é como erros deveriam ser — tipados, com contexto, com retry hints.** Nunca fazer string matching em `err.Error()`. **(9) Contract-first + code generation elimina duplicação entre linguagens.** Cosca precisa de adapters Go (runtime) + TypeScript (dashboard) + Python (scripts) — um contrato canônico com geração de código para cada um. **(10) AI workflows como workflows duráveis é exatamente o que a Cosca faz.** O temporalio/ai-cookbook valida nossa arquitetura: structured output, retry durável para LLM calls, agentic loops com cada passo gravado, human-in-the-loop como step normal. |
