## 2. DESCOBERTA MAIOR (o "chunker JSON escondido" da revisao)
O provider de embeddings do fluxo PADRAO (serve/CLI/testes) e o "local":
- nos TESTES: "local test-deterministic" (override deterministico);
- em PRODUCAO: "local TF-IDF" (internal/providers/local, tf-idf-local-v768) —
  vetores ESPARSOS, NAO semanticos.
O auto-detect so encontra ["local"] quando nao ha config explicita.
O NOMIC so foi usado no re-embed L364 (HTTP direto ao ollama) — as QUERIES
do fluxo padrao NAO sao embedadas com o nomic!
Implicacoes:
a) As buscas de producao usam queries TF-IDF contra um indice de vetores
   nomic/densos — MISMATCH; o recall real de producao e UNKNOWN e
   provavelmente DEGRADADO (os 0.989 medidos usavam vetores do indice como
   queries, nao o fluxo do provider).
b) O indice pode ser MISTO: originais (provider da indexacao original) +
   41.382 nomic (L364). Densidade 0% zeros nos dois grupos (nao distingue
   test-deterministic de nomic — ambos densos).
c) Tentativa de configurar EmbeddingProvider="openai"+baseURL ollama FALHOU
   (o Select caiu no local — o provider openai embeddings nao disponivel).
