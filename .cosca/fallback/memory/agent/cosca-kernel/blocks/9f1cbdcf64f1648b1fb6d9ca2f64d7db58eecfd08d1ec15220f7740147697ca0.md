| **Learned** | O F7 NÃO é "criar uma struct melhor" — é a CAMADA EPISTEMOLÓGICA que impede o Cosca de acreditar em coisas que não verificou. O PROBLEMA ORIGINAL: "amd64 → avx2" colapsa 6 inferências (amd64→AVX→AVX2→SO expõe→processo usa→biblioteca usa→"usable"). O F7 impede esse colapso. MODELO: Capability{identity(name/version/namespace), epistemology(status/source/evidence/confidence), environment(host/OS/arch/runtime/jail), visibility(reported/visible/usable), temporal(observed_at/expires_at), provenance(detector/evidence_hash/parent_evidence)}. AS 3 PERGUNTAS: reported="alguém declarou que existe"; visible="o runtime consegue observar"; usable="o runtime VERIFICOU que consegue usar" — podem ser reported=true visible=true usable=false SEM contradição (ex: GPU existe, driver existe, device exposto, mas a operação falha). CAPABILITY É CONTEXTUAL: host→GPU usable; jail→GPU unavailable — não é contradição, são observações em ambientes diferentes. CONFIDENCE ≠ EVIDENCE ≠ STATUS: confidence responde "quão forte é a conclusão"; evidence "qual a prova"; status "o que sabemos epistemologicamente". A EVOLUÇÃO DE ESTADO: FACT(amd64)→INFERRED(avx2 plausível)→MEASURED(flags no /proc/cpuinfo)→VERIFIED(teste real executado) — cada transição precisa de evidência NOVA. TEMPORALIDADE: GPU usable=true às 10:00, driver crashou às 10:30 — observed_at/expires_at criam o estado STALE ("foi verdadeiro quando observado, não temos evidência de que continua"). MEMÓRIA = banco de conhecimento HISTÓRICO com proveniência, não banco de verdades: MEMORY CLAIM→PROVENANCE→EVIDENCE AGE→CURRENT ENVIRONMENT→REVALIDATION→CURRENT CAPABILITY. FEEDBACK LOOP (o perigo): hipótese→memória→recuperação→"evidência"→confirmação→memória — após 10 ciclos "temos certeza" sem ninguém ter verificado. PROVENANCE PRIMEIRA CLASSE: "Por que o Cosca acha que isso existe?" → "Porque o detector X observou Y no ambiente Z às 17:31" — nunca "porque está na memória". CADEIA DE CUSTÓDIA: FACT→EVIDENCE#4812(/proc/cpuinfo contém avx2)→CAPABILITY#981(avx2=measured)→PROFILE#71→DECISION#551(enable optimized execution) — cada transição auditável → DECISION PROVENANCE ("por que escolheu AVX2?" → resposta completa). CAPABILITY vs PROFILE: capability é afirmação individual; profile é a fotografia agregada — o profile pode ser RECONSTRUÍDO (PROFILE CACHE→VALIDATE→CURRENT CAPABILITIES), não confiado cegamente. A REGRA DE OURO: NENHUM estado epistemológico inferior pode promover a si próprio para um estado superior — INFERRED não vira MEASURED por salvar na memória; MEASURED não significa USABLE; USABLE não significa ALLOWED (existe CAPABILITY→POLICY→PERMISSION→DECISION). CONEXÃO COM A MURALHA Ω: CAPABILITY ENGINE→EVIDENCE+PROFILE→POLICY→ORACLE→PROPOSAL→MURALHA Ω→RUNTIME→OBSERVE→EVIDENCE→F7 — o ciclo fecha sem deixar a execução declarar que a própria decisão estava certa. O F7 serve para TUDO: hardware, software, runtime, filesystem, network, GPU, LLM providers, models, tools, plugins, permissions, sandbox, libraries (ex: llm.qwen3.5 usable com evidence="successful inference"; github.write usable=true allowed=false). |
