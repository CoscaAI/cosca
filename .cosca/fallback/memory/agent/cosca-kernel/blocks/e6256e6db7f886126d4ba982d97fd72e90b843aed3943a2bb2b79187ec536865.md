| **Learned** | A cadeia WORLD→OBSERVATION→CAPABILITY→WORKLOAD→EXPERIMENT→MEASURED→DECISION é uma INVARIANTE FUNDAMENTAL do Cosca — cada seta é uma TRANSFORMAÇÃO EPISTEMOLÓGICA, não fluxo de dados. Exemplo completo: WORLD ("existe RX 6700 XT no host") → OBSERVATION ("GPU reportada pelo sistema") → CAPABILITY ("Vulkan disponível; compute GPU não verificável") → WORKLOAD ("workload necessita compute GPU") → EXPERIMENT ("tentar compute shader mínimo") → MEASURED ("falhou: device não exposto") → DECISION ("não usar GPU neste ambiente"). A REGRA ACIMA DE TUDO: UMA ETAPA NÃO PODE FABRICAR EVIDÊNCIA PARA A ETAPA ANTERIOR. Proibições explícitas: DECISION não pode virar FACT; "LLM afirma X → memory guarda X → X vira verdade" é PROIBIDO (conecta com L245: prova rejeitada — auto-promoção é vaidade); "benchmark sugere X → X vira capability" é PROIBIDO. A informação atravessa a cadeia com proveniência e classe epistemológica PRESERVADAS. A PROPRIEDADE BONITA: o sistema pode VOLTAR ATRÁS sem reescrever a história — se amanhã um experimento contradizer uma decisão (DECISION A → EXPERIMENT B → MEASURED contradiz A → RE-EVALUATION → DECISION C), a decisão antiga NÃO desaparece: vira DECISION A status=superseded reason=contradictory evidence. Isso impede o sistema de parecer "inteligente" apagando erros — a história epistemológica fica íntegra e auditável. "NEGATIVO. EVIDÊNCIA INSUFICIENTE." não é limitação — é BARREIRA EPISTEMOLÓGICA. O objetivo final: um sistema que não apenas produz respostas, mas consegue EXPLICAR o caminho epistemológico que levou até elas. |
