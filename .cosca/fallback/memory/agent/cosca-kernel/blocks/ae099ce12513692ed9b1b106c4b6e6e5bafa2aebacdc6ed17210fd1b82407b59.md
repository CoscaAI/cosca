## DESCOBERTA METODOLOGICA (2a ordem — a mais importante)
O indice em producao (scoreParallel 16 workers) tem desempate NAO-
deterministico entre scores iguais (duplicatas de 1.0): o jaccard via Search
varia 0.82-0.96 entre execucoes. A FASE 8 (jaccard 0.82) estava CONTAMINADA.
Metodo correto: score deterministico (Go puro, desempate por rowid) sobre
snapshot unico. ERRATA L346: jaccard real do int8 = 0.965 (nao 0.82). E o
ranking de producao e INSTAVEL entre execucoes para queries com duplicatas
massivas — problema de produto real.

## A-sub — int16 real (deterministico)
int8:  recall@1 0.995 / @10 0.978 / jaccard 0.965 / NDCG 1.0
int16: recall@1 1.0 / @10 0.996 / jaccard 0.992 / NDCG 1.0 / top-1 NUNCA muda
(0/200) / maxerr 0.0019 — praticamente oracle. int16 confirma-se como default
de maxima fidelidade; int8 e excelente (0.965).
