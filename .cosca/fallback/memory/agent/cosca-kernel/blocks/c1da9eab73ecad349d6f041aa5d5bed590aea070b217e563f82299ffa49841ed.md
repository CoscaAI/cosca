| **Learned** | **(1) GOTCHA CRÍTICO — encoding/json do Go casa campos case-INSENSITIVE: a Binance manda `e` (tipo, string) E `E` (event time, número) no MESMO payload; SEM declarar `EventTime int64 \`json:"E"\``, o número estoura ao casar com `Event string \`json:"e"\`` → "cannot unmarshal number into Go struct field .e". O mesmo ocorre DENTRO de `k`: `l` (low, string) vs `L` (last trade id, número) e `v` (volume) vs `V` (taker volume). A regra de ouro: para APIs que usam pares maiúsculo/minúsculo (Binance, OKX...), declarar TODOS os campos com tipo certo — nunca confiar no matching exato.** **(2) Testes com payload de EXEMPLO sem os campos reais deixam o bug passar: meus testes de parsing não tinham `E`/`L`/`V` e passaram, mas o stream real estourou. SEMPRE testar com um payload REAL capturado.** **(3) Debug de parsing de stream = dumpar a mensagem crua que falhou (log do raw data no loop de leitura) — foi isso que revelou o `E` numérico em 30 segundos.** **(4) A separação adapter→normalização (exchange → domain.Tick/Candle) → evento (market) replica o padrão "connector" do cosca-node: o núcleo nunca conhece o protocolo da corretora.** **(5) nhooyr.io/websocket exige 1 reader + 1 writer; o buffer de subs + re-assinar na reconexão resolve a ordem "Subscribe antes de Connect" de forma robusta.** **(6) `pkill -f` e `pkill -x` matam a própria shell se o pattern casa com o command line do bash — usar `pkill -x <nome do binário>` (match exato) ou pgrep do PID.** |
