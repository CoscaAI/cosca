## L26 — 2026-08-10 — CSS 404 no HornFit web: `next build` corrompeu o `.next` do `next dev` ativo | Level 3

| **Technique** | Level 3 — **(1)** Diagnóstico visual via puppeteer headless com 3 scripts: (a) fetch de login em `about:blank` falhou por falta de origin — lição: navegar primeiro (`page.goto`) antes de `page.evaluate` com fetch; (b) varredura de rotas com computed styles (`getComputedStyle(document.body).fontFamily/backgroundColor`) + contagem de `cssRules`; (c) captura de `response` com status >= 400 revelou o 404 exato. **(2)** Sinais: `fontFamily: "Times New Roman"` + `bodyBg: rgba(0,0,0,0)` + 0 cssRules = Tailwind NÃO aplicado. **(3)** Cause: `/_next/static/css/app/layout.css` → **404**. Root cause: rodei `npx next build` ENQUANTO `next dev` rodava — ambos compartilham o diretório `.next`; o build de produção corrompeu o cache do dev. **(4)** Fix: kill `next dev` (via `ps aux | grep next`), `rm -rf .next`, restart com `nohup setsid npm run dev` (web/apps). **(5)** Validação final: login E2E via UI (preenchimento de form com `Object.getOwnPropertyDescriptor(el.__proto__, 'value')` + `input` event bubbles), navegação client-side via clique no sidebar, conferindo h1, rows do tbody e font. |
