### 2026-07-30 — F2.1 ★ Cognitive Economy Engine — STAR da Fase 2

**Técnica**: Design do modelo de ROI cognitivo pós-task com 3 componentes de custo (tokens, tempo, atenção) × 3 componentes de valor (aprendizado, reuso, prevenção), ajustado por entropia cognitiva (F1.6).

**Domínio**: architecture, cognitive-economy, analytics, roi-measurement

**Contexto**: Reformulação completa do Cognitive Economy Engine (SKILL.md) de v1.0.0 (engine de eficiência pré-task com 5×5 dimensões) para v2.0.0 (★ F2.1 STAR — ROI cognitivo pós-task com 3×3 dimensões + entropia).

**Aprendizados**:

1. **Dois modelos complementares no mesmo engine**: O engine agora opera em dois modos — PRÉ-TASK (efficiency_score como advisor) e PÓS-TASK (ROI como contador). O pre-task usa 5 dimensões de custo (incluindo compute + storage) para decisão; o pós-task usa 3 dimensões simplificadas para accounting rápido (< 100ms). Ambos compartilham a mesma base conceitual.

2. **ROI = (V-C)/C é mais intuitivo que efficiency_score = V/C**: Don e agentes entendem "percentual de retorno" mais naturalmente que "score de eficiência". A fórmula de ROI permite thresholds claros (200% = excelente, 100% = bom, 0% = médio, negativo = prejuízo) que mapeiam diretamente para decisões de negócio.

3. **Entropia como redutor de ROI é o insight mais importante**: Conhecimento desorganizado reduz o valor real do que é produzido. A entropia atual de 64.5% corta o ROI em 64.5% — um efeito massivo que conecta a qualidade da base de conhecimento diretamente ao balanço econômico do sistema.

4. **Tasks de infraestrutura têm ROI negativo imediato**: Tasks como F7-memorize-workflow (-88.8% ROI) e F3-agent-engine (-26.9% ROI) são investimentos de capital intelectual. O ROI real emerge do reuso futuro. O engine não bloqueia estas tasks — apenas alerta e monitora o ROI acumulado.

5. **Valor de prevenção de bug domina o ROI quando presente**: A task F6-mcp-deadlock-fix (+117.8% ROI) demonstra que o maior valor não vem de aprender ou reusar, mas de prevenir custos. O valor de prevenção ($0.475) foi 4× maior que aprendizado + reuso combinados ($0.050). Isso valida o peso alto (0.45) para prevenção na composição de valor.

6. **Pipeline < 100ms é viável com cache de entropia**: Custo total de 82ms (10ms coleta + 5ms custo + 5ms valor + 2ms ROI + 50ms entropy cache + 10ms registro). O cache de entropia com TTL de 300s é a chave para performance — sem cache, a consulta levaria 200ms+.

7. **Dashboard de top 5/bottom 5 agentes por ROI é acionável**: Agentes com ROI consistentemente alto (cosca-cli: +240%) devem ser priorizados para tasks similares. Agentes com ROI negativo (cosca-kernel: -88%) geralmente executam tasks de infraestrutura — não é um problema do agente, mas do tipo de task.
