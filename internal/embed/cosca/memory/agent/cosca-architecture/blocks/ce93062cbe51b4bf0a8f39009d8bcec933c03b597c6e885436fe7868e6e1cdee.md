### 2026-08-04 — Competitive synthesis: evidence-calibrated architecture for Don mission

**Técnica**: Síntese competitiva multi-repositório com normalização de evidência, separação fato/inferência/hipótese e matriz de cross-pollination sem adoção de dependência.
**Domínio**: architecture, competitive-analysis, durable-execution, evidence-calibration, agent-platforms
**Contexto**: Leitura de `cosca-baseline.md` e sete relatórios `research-*.md`, fixados por SHAs de Cosca, AutoGen/Magentic-One, Dify, PydanticAI, DeerFlow, OpenHands, LangGraph, MetaGPT, Mastra, Google ADK, OpenAI Agents SDK e Microsoft Agent Framework. Produção de `/tmp/opencode/competitive-synthesis.md`, sem implementação.
**Nível**: 4
**Outcome**: success

**O que foi aprendido**:

1. Os rótulos E0-E5 não são globalmente comparáveis quando relatórios usam taxonomias diferentes; a síntese deve preservar os rótulos de origem e declarar uma convenção harmonizada, sem elevar documentação a fato.
2. A unidade correta de comparação é o contrato comportamental (crash/resume, ownership, idempotência, sandbox, capability de provider, ACL de memória), não a lista de features ou o número de agentes/providers.
3. A fronteira arquitetural mais recorrente no ecossistema é `planner adaptativo -> workflow determinístico -> tool/policy gateway -> durable ledger`; ela combina ledger de Magentic/DeerFlow, checkpoint de LangGraph/Dify e governança do Cosca sem copiar frameworks inteiros.
4. “Persistência de estado” tem pelo menos cinco semânticas distintas: histórico, snapshot de objeto, checkpoint de workflow, durable run e efeito externo confirmado. Misturá-las produz claims falsos de exactly-once/resume.
5. Cosca tem vantagem de posicionamento em produto governado/local-first, mas não prova vantagem em autonomia longa; `go test ./...` é baseline de pacote, não baseline de comportamento operacional.
6. Cross-pollination segura é seletiva e deve preservar invariantes Cosca: policy fora do prompt, memory untrusted-by-default, idempotency key em efeitos e sandbox fail-closed.

**Próximo passo**: aplicar os dez experimentos da síntese começando por crash/resume, fencing e sandbox; só depois avaliar browser/voice e mais autonomia.
