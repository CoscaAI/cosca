### 2026-08-06 — Frontend Enterprise Redesign: arquitetura de cockpit unificado para Cosca Console

**Técnica**: Síntese arquitetural completa do frontend Cosca — mapeamento de 86 endpoints REST para estratégia de 3 camadas (React Query + SSE + WebSocket), design system Tokyo Night Evolved, consolidação de 40+ páginas em 6 hubs de comando, stack de visualização com Recharts + D3 helpers.

**Domínio**: architecture, frontend-enterprise, real-time-monitoring, design-system, dashboard-unified

**Nível**: 4 | **Outcome**: success

**O que foi aprendido**:

1. **3 camadas de dados, não uma só**: React Query para dados estruturados com cache (~70 endpoints), SSE para streams de processo (~5 endpoints), WebSocket para métricas em tempo real (~10 tópicos). Cada camada resolve um problema diferente — latência, cache, push. O backend Cosca já tem as 3 infraestruturas prontas (EventSource, WS Hub com topic pub/sub, REST handlers); o frontend só precisava consumi-las corretamente.

2. **6 hubs, não 40 páginas**: A redução de 26 itens de menu para 6 hubs principais (Command Center, Security Center, Analytics Hub, Orchestration Hub, Knowledge Hub, AI Tools Hub) segue o princípio de cognitive load — cada hub agrega visualizações de múltiplos domínios relacionados (ex: Security mostra threat dash + audit + API keys + kernel emergency juntos). Drill-down preserva acesso granular sem poluir a navegação.

3. **Tokyo Night Evolved, não Tokyo Night genérico**: O tema atual (hsl 240° 10% 3.9%) é um dark mode funcional herdado do shadcn/ui. A evolução adiciona: profundidade com 3 camadas de background (base → card → popover), glass morphism (backdrop-blur em overlays), brand accent (Cosca blue #5162f0 como primary), 5 cores de status semânticas, paleta de 8 cores para gráficos, e design tokens completos (tipografia, spacing, shadows, transitions).

4. **Recharts sobre Nivo/visx/Tremor**: Decisão de manter Recharts (já instalado, theme-aware, 45KB tree-shaken) com adição de D3-scale + D3-shape (~12KB) apenas para gráficos que Recharts não cobre nativamente (Sankey, Treemap). Nenhuma dependência grande nova — preservar bundle budget de 200KB por rota.

5. **Server Components como shell, Client Components como folhas**: A arquitetura atual trata tudo como "use client". A migração para RSC nos layouts e wrappers (com streaming SSR do Next.js 15) reduz JS enviado ao cliente e melhora FCP/TTI. Apenas componentes interativos (charts, forms, hooks) permanecem como client boundary.

6. **WebSocket complementa, não substitui, React Query**: O padrão `useLiveMetric` combina o melhor dos dois mundos: valor inicial do cache react-query (com stale-while-revalidate), updates em tempo real via WS, fallback ao query no reconnect. Isso resolve o problema de "dado inicial vs live" sem duplicação de estado.

7. **Cobertura atual 75%, gaps mapeados**: 25% dos endpoints (agentbridge UI completa, traces replay/causal, workflow run/stream, knowledge index/sync, skills install) não têm representação visual no frontend. O plano de implementação em 3 fases cobre todos esses gaps.

8. **Acessibilidade em gráficos é tabela invisível**: Gráficos Recharts não são acessíveis nativamente. A solução é uma `<table className="sr-only">` paralela com os mesmos dados — screen readers leem a tabela, usuários visuais veem o gráfico. Padrão aplicável a todos os tipos de chart.
