**Key Learnings**:

1. **`atomic.Pointer` for shared server state.** The classic race between `Serve()` writing `httpServer` and `Shutdown()` reading it is eliminated by using `atomic.Pointer[http.Server]` with `Store()` in Serve/ServeTLS and `Load()` in Shutdown. The nil check becomes implicit: `Load()` returns nil before Store is called.

2. **Deep copy while holding lock for sequential consistency.** `SaveSession()` released the RLock before reading `s.Messages`, while `AppendMessage()` wrote to `s.Messages` under Lock. Fix: acquire write lock (Lock), deep-copy all fields (ID, Model, Agent, Messages slice, Metadata map), then release the lock before doing I/O. This ensures a consistent snapshot without blocking concurrent I/O.

3. **Signal handler ordering matters.** `signal.Notify()` must be called BEFORE launching server goroutines. Any signal arriving between goroutine startup and `signal.Notify()` is lost (or kills the process). Using `sync.WaitGroup.Add(1)` before each `go func()` and `startWg.Done()` as the first instruction (not deferred) in each goroutine ensures `startWg.Wait()` blocks until all goroutines are scheduled and registered.

4. **Shared `io.Writer` needs a shared lock.** `OutputFormatter.Warning()` and `Spinner.Start.func1()` wrote to the same `bytes.Buffer` with separate mutexes, causing a data race. The fix: wrap the writer in a `syncWriter{mu, w}` that serializes all writes through a single mutex, and pass the same `*syncWriter` to both `OutputFormatter` methods and `Spinner`/`ProgressBar` constructors.

5. **Previous fix patterns validated:**
   - **Global state + goroutine:** `sync.RWMutex` with double-check locking + `atomic.Pointer` for cached instances (used in `internal/chat/registry.go` and `internal/embeddings/provider.go`)
   - **Stats counters:** `atomic.AddInt64`/`atomic.LoadInt64` (used in `internal/circuitbreaker/circuitbreaker.go`)
   - **Server/Shutdown:** `atomic.Pointer[http.Server]` with Load/Store
   - **Signal race:** `sync.WaitGroup` + `signal.Notify` ordering
