**Key Learnings**:

1. **The nil-store guard in `audit.go List` runs BEFORE `parseTimeParam`/`parseInt64`.** The old `TestParseTimeParam*`/`TestParseInt64Valid` tests used `NewAuditHandler(nil)` so they only ever hit the 503 branch — that's why parseInt64 sat at 0%. You MUST use a real store + `from`/`to` params to cover the parsers. Use an isolated temp-file store (`audit.NewStore(t.TempDir()+"/audit.db")`) for count assertions: `newTestAuditStore` uses `:memory:?cache=shared` which is ONE shared DB across the whole process, so "empty"/"total==N" assertions are unreliable with it.

2. **`r.PathValue("id")` works in httptest via `req.SetPathValue("id", ...)`** — handlers read path params directly; no router needed.

3. **Users/API-key handlers are directly testable with in-memory stores**: `internalauth.NewUserStore(UserStoreConfig{})` and `internalauth.NewAPIKeyStore(APIKeyStoreConfig{})` (DataDir="" = in-memory, no bcrypt/db cost beyond the hash on Create). `UserStore.GetByUsername` returns a pointer to the cached user, so mutating `user.LockedUntil` directly is a fast deterministic way to cover the Login 429 lockout pre-check.

4. **BUG (documented, not fixed): `UsersHandler.UpdateRole` returns 400 for a non-existent user, not 404.** `users.go:143-146` maps `ErrUserNotFound` to `http.StatusBadRequest` (the same 400 used for invalid role). Test asserts the actual behavior; fix belongs in production code.

5. **BUG (documented, not fixed): API keys allow duplicate names.** Neither `APIKeysHandler.Create` nor `APIKeyStore.Generate` enforces name uniqueness — two keys with the same name both return 201 with distinct IDs. Test documents the behavior.

6. **`internalauth.Claims` for context injection**: `context.WithValue(ctx, apiauth.ContextKeyClaims, &internalauth.Claims{Sub, Username, Role, Type})` — matches `api/auth.Middleware` behavior and drives `created_by`/role in apikeys Create, plus Me/Register paths.

7. **Audit List/Get semantics**: `List` NEVER 404s — a non-matching filter returns 200 with `entries: []` and `total: 0`. `Get` 404s only when `GetByID` returns `(nil, nil)` (not `sql.ErrNoRows` — that maps to nil, nil in the store). The 500 path in Get (store error) and the 500 in List (store.List error) are effectively unreachable with a healthy in-memory/file store — skip them.

8. **Other agents were working in the same `handler_test` package concurrently** — `secrets_test.go` briefly redeclared `TestSecretsDeleteInvalidJSON` (already present in `handler_coverage_test.go`), breaking `go vet`/test for the whole package. Resolved by the other agent renaming to `TestSecretsDeleteMalformedJSON`. Re-run verification after others commit; transient "build failed" states are expected mid-flight.
