**Key Learnings**:

1. **Black-box testing of handlers with real Runtime.** The handler methods (`Status`, `Health`) call methods on `*runtime.Runtime` that are all public (`State()`, `HealthReport()`, `Config()`, `Health()`). We can use `runtime.New()` directly instead of mocking — simpler, and no risk of mock drift. The stateless nature of `Runtime` before `Start()` is called (no goroutines, only callback registration) makes this pattern safe.

2. **State transition validation matters.** The first attempt at the "ready with components" test used `TransitionTo(StateReady)` directly from `StateUninitialized`, which is an invalid transition. Valid transitions must go through `StateInitializing` first per the `validTransitions` map. Always cross-reference the state machine definition when manipulating runtime state in tests.

3. **SSE testing with cancellable contexts.** Testing the `StatusStream` (SSE) handler requires: (a) `stream.NewSSETestWriter()` which implements `http.Flusher` (unlike `httptest.ResponseRecorder`), (b) a cancellable request context injected via `req.WithContext(ctx)`, (c) starting the handler in a goroutine, (d) cancelling the context to break the infinite loop, (e) a `done` channel to wait for handler return. A 50-100ms sleep before cancellation ensures the initial SSE event is written before the loop terminates.

4. **`SetHub` is non-verifiable in black-box tests.** The `hub` field in `RuntimeHandler` is set by `SetHub` but never read by any handler method in the current code. Black-box tests can only verify that calling `SetHub` does not panic. Behavior verification would require white-box access or a future handler method that uses the hub.

5. **Hub cleanup in tests.** `stream.NewHub()` starts a background goroutine (`go h.Run()`). Every test that creates a Hub must call `hub.Shutdown(ctx)` in a deferred cleanup to avoid goroutine leaks.
