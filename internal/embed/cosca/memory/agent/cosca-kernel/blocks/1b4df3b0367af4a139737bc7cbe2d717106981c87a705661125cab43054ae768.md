| **Learned** | (1) MLIR: IR multi-nível (dialects) — o programa desce de nível: tensor→linalg→affine→scf→arith→vector→memref→gpu→llvm. Lowering incremental com legalidade declarativa (ConversionTarget: legal/ilegal/dynamic) + rewrite patterns + TypeConverter + materializations. PassManager hierárquico (module→func→any), analyses separadas lazy com invalidação declarativa, passes op-agnostic com filtro por interface. Block args em vez de PHI + IsolatedFromAbove. GRAPH REGIONS: região sem CFG, ops=nós, values=arestas, ciclos permitidos — exatamente a semântica do node graph do Cosca. (2) LLVM: SSA (cada valor definido uma vez, domina usos) — base de toda otimização segura. Passes padrão: instcombine, GVN/CSE, DCE/ADCE, LICM, loop-fusion, inlining com cost-model, constant folding, vectorização. Mesmo IR → múltiplos backends (X86/ARM/RISC-V/NVPTX/AMDGPU/SPIR-V) — só o codegen diverge. Codegen em estágios com invariantes verificáveis (IRTranslator→Legalizer→RegBankSelect→InstructionSelect). (3) IREE: TIMELINES + FENCES — invocações agendadas contra timelines (fence = timeline+inteiro, wait/signal), execução OUT-OF-ORDER tipo Tomasulo; frontiers (vector clocks {axis→epoch}) com merge/dominance → wait elision (custo zero), buffer reuse O(1) via death frontiers, submit-before-wait. HAL (hardware abstraction layer): interface uniforme device/buffer/queue/command_buffer/semaphore, drivers CPU/Vulkan/CUDA/HIP. Stream-ordered allocations + pooling (alocar é agendado; peak memory ~1 invocação). |
