| **Agent** | cosca-kernel |
| **Task** | Don quer criar projetos de clientes FORA do root cosca — sempre em projects/ — para o root ficar limpo e a jail funcionar no projeto do cliente: "o cosca-forex dentro do root projeto, qual a melhor forma de nos criar projetos e nao poluir o root?" |
| **Technique** | Level 4 — Novo grupo de comandos `cosca project` (internal/cli/project.go): `new <name>` cria scaffold em ~/Documents/projects/<name>/ (README, .gitignore, .cosca/{manifest,constraints,config.yml,state.yml}, src/docs/tests/scripts com .gitkeep, git init), `list`, `open`, `remove --force`. Override via env COSCA_PROJECTS_DIR. Root cause insight: o embed do framework é compilado DENTRO do binário (go:embed), então cosca roda de QUALQUER diretório — nenhum arquivo do framework é necessário nos projetos de clientes. A jail monta os.Getwd() como workspace root, então rodar `cosca terminal` dentro de um projeto de cliente monta O PROJETO DO CLIENTE como / — isolamento perfeito (framework invisível, /home invisível, projeto rw, go/git disponíveis). |
