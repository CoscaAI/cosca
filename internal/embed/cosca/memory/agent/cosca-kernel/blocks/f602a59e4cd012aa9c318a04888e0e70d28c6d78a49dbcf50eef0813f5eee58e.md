# L350 — Investigacao da ORIGEM das 752 copias (e dos orfaos)

## Pergunta (do professor): quem cria 752 copias de um vetor?
Resposta: o CHUNKER embeda separadores "---" (markdown) e conteudo vazio
como chunks; uma leva de ingestao em 2026-08-16 (743 das 752 copias criadas
nesse dia) processou centenas de documentos com "---", gerando embeddings
identicos de lixo.

## Duas componentes da duplicacao
A) TRIVIAIS (separadores/vazio/<10 chars): 12.4% dos chunks com vetor (1.735)
   + 18.8% dos orfaos (9.164). 44 grupos de vetores duplicados. Bug de
   chunkizacao — filtro de conteudo minimo resolve. Inclui os gigantes
   (752x "---", 655x vazio).
B) CONTEUDO REAL repetido (templates/blocos embutidos): 670 dos 714 grupos
   duplicados. Documentos que EMBUTEM os mesmos blocos: AGENT_PRIMER.md
   (61x), instrucoes de auto-evolucao (56x), trechos de memoria (54x), etc.
   Cross-documento (95.6%). Dedup por conteudo resolve.
Metadata dos triviais: vazia ({}) — o processo de ingestao nao registra
origem (source path ausente).

## DECISION (nada implementado — investigacao termina aqui)
Correcoes candidatas (avaliar em fase propria):
1. Chunker: filtrar chunks triviais (comprimento util minimo, ignorar
   separadores puros) — remove 12.4% dos vetores + 18.8% dos orfaos.
2. Ingestao: deduplicar por conteudo na aquisicao (evitar re-embedar o
   mesmo bloco 752x).
3. Dedup pos-hoc (limpeza) com backup — depois de corrigir a causa.
A otimizacao mais barata do sistema inteiro: parar de colocar a mesma coisa
752 vezes.
