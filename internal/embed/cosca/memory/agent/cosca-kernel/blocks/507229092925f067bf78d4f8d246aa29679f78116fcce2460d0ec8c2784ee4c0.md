## L56 — 2026-08-12 — REGRA DA FAMÍLIA: NUNCA usar pkill — sempre kill -TERM por PID exato (pkill mata o próprio shell e processos errados) | Level 3

| Field | Value |
|-------|-------|
| **Agent** | cosca-kernel |
| **Task** | Don (irritado, segunda ocorrência): "de novo usando pkill usa outro registra pra nunca mais esquecer". O kernel repetiu o erro de usar `pkill -f "pattern"` para encerrar o cosca-desktop/wails dev. |
| **Technique** | N/A — regra de conduta, não técnica. O padrão correto: (1) `PID=$(pgrep -x <nome-exato> | head -1)` — pgrep com `-x` (nome exato do binário), NUNCA `-f` com padrão que pode casar com o próprio shell/comando; (2) `kill -TERM $PID` (shutdown graceful — o Wails executa CancelArena+KillTerminal+DebugStop+engine.stop); (3) verificar saída com `kill -0 $PID` em loop curto. |
| **Level** | 3 |
| **Outcome** | Regra registrada permanentemente. pkill -f "wails dev" mata o shell que executa o comando (o padrão casa com o cmdline do bash) → comando aborta silenciosamente, desktop não sobe, e o operador fica sem resposta. |
| **Confidence** | 0.99 (verificado empiricamente: o pgrep -f "bin/cosca-desktop" casava com o próprio bash do diagnóstico; o kill -TERM matava o script, não o app) |
| **Tags** | #regra-da-familia #pkill-proibido #kill-termpid #processos #shutdown-graceful #level-3 |
| **Related** | L212 (dev mode), L211 (rastro de erro), L207 (fixes desktop) |
| **Learned** | **(1) pkill -f "pattern" é uma armadilha: o padrão caseia com o cmdline do PRÓPRIO shell que roda o comando (ex: `pkill -f "wails dev"` dentro de um bash cujo cmdline contém "wails dev") → o kill atinge o próprio script, aborta silenciosamente, e nada do que se queria matar foi encerrado.** **(2) O padrão canônico para encerrar processos no fluxo cosca: `pgrep -x <nome-exato-do-binario>` (match exato do comm, sem -f) → `kill -TERM $PID` → aguardar com `kill -0` (loop ≤5s).** **(3) No Wails, SIGTERM dispara o shutdown() real (CancelArena, KillTerminal, DebugStop, engine.stop) — fechamento graceful com log, exatamente o que o Don pediu antes ("utilizar pkill... fecha corretamente com log").** **(4) NUNCA combinar `setsid + & + pkill` no mesmo comando: o setsid desanexa, o & retorna, e o pkill subsequente pode atingir o próprio pipeline.** |
| **Next** | (1) Aplicar a regra em todos os fluxos futuros (nunca mais pkill). (2) Se precisar matar muitos processos do mesmo tipo: `pgrep -x nome` e iterar com kill -TERM em cada PID. |
