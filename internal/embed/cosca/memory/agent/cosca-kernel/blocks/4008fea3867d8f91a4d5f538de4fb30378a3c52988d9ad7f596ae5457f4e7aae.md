| **Learned** | **(1) O confundidor mais sutil da ablação é o MAG: usar o runner completo (orquestração) para propor candidatos injetaria a memória do próprio Cosca no prompt, então a condição "alone" (histórico vazio) NÃO seria amnésica — o MAG traria memória por baixo dos panos. A correção é o chat mínimo (`registry.Chat` direto), que garante que a ÚNICA memória que o sujeito vê é a que o harness passa.** **(2) O prompt do LLMSolver tem 3 invariantes: (a) nunca contém o segredo/referência, (b) nunca dá dica de como resolver (sem viés), (c) a única diferença entre alone/managed é a seção de histórico — tudo mais é byte-idêntico.** **(3) "Responda SÓ o valor" + `ParseLastLine` resolve a extração do candidato de forma robusta sem precisar de parsing estruturado frágil.** **(4) "Adivinhe o número" é um problema INVÁLIDO para medir descoberta em LLM: não há estrutura para raciocinar, só chute — o problema real precisa ter espaço de busca explorável por raciocínio (o ledger/otimização de índice serve).** **(5) Temperatura 0 + mediana+IQR em N≥5 é a dupla de mitigação de não-determinismo, mas o provider pode não honrar temperature 0 — registrar como limitação. |
