# L355 — Comparacao de alternativas de correcao (A/B/C/D, em memoria)

## Experimento (read-only, replicas em memoria — nada de producao)
Parser alternativo (parseGrouped) replicando o parser do Cosca com a regra
de agrupamento; ChunkDocument de PRODUCAO processa os nos. Metricas por
regra: n chunks, <=25 chars, triviais, headings/code/listas preservados.

## Resultados (MEASURED, na replica)
Caso critico (JSON grande 30.604 chars — o caso real de 1.500 chunks):
  baseline: 1.500 chunks (80% <=25 chars)
  A:        9 chunks  (0% <=25)  — resolvido na raiz
  D:        9 chunks  (0% <=25)  — identico a A nos casos testados
  B:        301 chunks — paliativo (merge so pega <=25; fragmentos 26-100
            chars continuam)
  C:        JSON valido -> 1 chunk; JSON invalido (trailing comma) ->
            fallback baseline (1.500). C so ajuda JSON valido.
json-1 (192 chars): baseline 8 (87.5% <=25) -> A/B/C/D: 1-2 chunks.
md-2 (texto+code+lista): baseline 8 -> A/D 6, B 7, C 8. Fronteiras
  PRESERVADAS (h=1 c=1 l=1 em todas as regras no md-2).
md-1 (markdown bem formado): todas as regras = 7 (sem fragmentacao — paridade).
Casos de seguranca: nenhum conteudo perdido ("Go 1.26", URLs, etc.) em
nenhuma regra (teste PERDIDO passou).

## Analise
- A (CommonMark) resolve na ABSTRACAO CORRETA (o parser): 1.500 -> 9 com
  fronteiras semanticas preservadas. O splitLongParagraph ja agrupa bem
  quando recebe o bloco (9 chunks de ~2.550 chars — controle da L354).
- D == A nos dados (guarda extra irrelevante nos casos reais).
- B e paliativo: melhora (1.500 -> 301) mas nao resolve; nao toca o parser.
- C e a excecao especifica (parser Frankenstein): so JSON valido; nao ajuda
  markdown/codigo/texto. Desconfianca do Don confirmada.

## DECISION (proposta para L356)
Recomendacao: A (agrupar linhas de paragrafo consecutivas sem blank line no
parser markdown — padrao CommonMark). D como variante conservadora
equivalente se a revisao preferir. B/C descartadas (paliativo / excecao).
Implementacao real no parser de PRODUCAO = HYPOTHESIS (a replica e fiel nos
casos principais; a validacao real e a L356). Nada implementado agora.
