| **Learned** | **(1) A fábrica já existia — 34 arquivos em `internal/pipeline/` com Planner, StepRunner, RecoveryLoop, DoD, CMI, PostTaskHook, Reconciler, PluginRegistry, CheckpointStore, WorkflowHistory. 39 workflows definidos. Mas o `cosca capability level` roda como processo separado (do terminal), então as env vars do systemd não são herdadas. Camadas: env vars → TCP dial → viper config. **(5) O padrão de 3 camadas (env var → live check → config) é o modelo canônico para qualquer detecção de estado no Cosca: a jaula bloqueia filesystem e systemd, mas não bloqueia TCP local.** **(6) A integração do pipeline no bootstrap seguiu o padrão de menor atrito: adicionar campos ao `Result` existente + criar seção condicional em `Compose()` + gate via `PipelineConfig.Enabled`. Sem refatoração agressiva do bootstrap.**
