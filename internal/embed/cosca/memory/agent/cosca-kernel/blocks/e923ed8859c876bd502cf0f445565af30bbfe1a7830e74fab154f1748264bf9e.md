PONTOS-CHAVE NOVOS: (1) physical_capacity ≠ visible_capacity ≠ effective_capacity — host 64 cores / container quota 8 / effective 8; otimizar para effective. (2) NUMA como cidadão de primeira classe: local vs remote bandwidth MEDIDO experimentalmente (1 node 42 GB/s vs 2 nodes 76 GB/s vs poor placement 51 GB/s); nunca modificar afinidade automaticamente na fase 1 (só OBSERVE/MEASURE/REPORT). (4) HARDWARE FINGERPRINT técnico (vendor/model/arch/features/topologia/caches/NUMA/GPU/env) SEM dados pessoais — para matching de perfil/histórico. (5) PROVENANCE DE PERFORMANCE: guardar workload+dataset+dim+hardware+env+config+mean+stddev+runs+baseline+speedup+confidence+evidence (benchmark-id/hash). (6) CONFIANÇA ESTATÍSTICA: mean/min/max/stddev/CV; classificar HIGH/MEDIUM/LOW/INCONCLUSIVE — nunca "recorde" por 0.01 de diferença. (7) GUARDAR TAMBÉM EXPERIMENTOS REJEITADOS (Norms 10.6 REJECTED "slower than baseline"; Unroll4 12.5 INCONCLUSIVE "within noise") — memória experimental; otimização refutada = conhecimento útil.
