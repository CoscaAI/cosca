| **Learned** | **(1) O salto "registra→otimiza" é concreto: `evaluatePrompt` (oráculo como fitness) + mutação reflexiva + seleção = GEPA-equivalente. O oráculo que construímos (L242) É a fitness — exatamente como o PLAN.md do Hermes descreve (fitness task-específica).** **(2) Achado honesto: a fitness tem um FLOOR natural (5 seed errados + 1 refine certo = 6 attempts) — quando o baseline já está no floor, a evolução NÃO tem espaço para melhorar, e o resultado honesto é "sem melhoria", não um número forjado.** **(3) Para demonstrar melhoria mensurável, a task precisa ter baseline RUIM (ex.: prompt default que FALHA e a evolução conserta) — o "evolve de falha pra sucesso" é mais convincente que "evolve de 6 pra 6".** **(4) A mutação reflexiva (o LLM vê o prompt + resultado e propõe variantes) é o coração do GEPA — e funciona, mas depende do LLM seguir o formato de separador; se não segue, as variantes colapsam (observado: só 1 variante por rodada em vez de 2).** **(5) Overfit é um risco real: a evolução pode "melhorar" o prompt hardcodando a resposta ("tente x² primeiro") — isso é trapaça, não descoberta; o gate de generalização (benchmark-as-gate) é o que falta para distinguir. |
