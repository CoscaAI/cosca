Comandos `knowledge graph`, `graph show`, `graph stats` usavam `graph.New()` direto (nem o adapter chamavam) e `graph export` só mostrava spinner sem escrever arquivo. **ARMADILHA DO DRIVER:** `sql.Open("sqlite3", ...)` com modernc registrado como "sqlite" falha SILENCIOSO (erro ignorado com `_ =` e grafo vazio) — o teste unitário pegou isso. **ARMADILHA DA JAULA (2 bugs):** (1) caminho absoluto do host (`/home/cosca/...`) não existe dentro da bolha (workspace = "/") — export com `-o /abs` falhava com "no such file or directory" engolido pelo SilenceErrors + stderr do bwrap; debug via arquivo `.cosca/export-debug.log` dentro do workspace (visível do host) é o jeito; (2) `--setenv COSCA_PROJECT_DIR` era colocado ANTES do `--clearenv` → varrido junto com tudo; a ordem é: `--clearenv` primeiro, TODOS os `--setenv` depois (o bwrap processa em ordem, o último setenv vence). **SOLUÇÃO:** adapter carrega entities (id, entity_type, name, path) + relationships (source_id, target_id, rel_type, weight) via modernc/sqlite; query resolve nome/path → UUID (IDs são UUIDs, usuário busca por nome); resultados mostram nomes legíveis; export reescreve caminho absoluto → relativo via COSCA_PROJECT_DIR (que agora sobrevive); teste de integração com DB fake cobre carregamento/export/query/stats. **PARA A CASA:** (a) nunca ignore erro de Open/Query com `_ =` em adapter — devolve grafo vazio sem diagnóstico; (b) qualquer env setado para a jaula vem DEPOIS do --clearenv; (c) testar adapters com DB fake em memória, não com path absoluto da máquina (frágil); (d) stderr dentro da jaula é engolido — para debugar, escrever log em arquivo dentro do workspace. |
