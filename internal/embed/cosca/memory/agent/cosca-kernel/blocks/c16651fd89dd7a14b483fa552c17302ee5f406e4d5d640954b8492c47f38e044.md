| **Learned** | **(1) "Estado durável" exige que a PERSISTÊNCIA grave o modelo COMPLETO, não um subconjunto: antes, PersistEvent só gravava type/timestamp/run_id/entity_id/payload — os campos event_id/causation_id/severity (adicionados no L255) eram PERDIDOS no disco, então o causal/time-travel não sobreviveria a restart. Migrar o schema é parte de introduzir um campo novo.** **(2) SQLite não tem `ADD COLUMN IF NOT EXISTS` — o jeito é `PRAGMA table_info` + `ALTER TABLE` condicional; e o `CREATE TABLE IF NOT EXISTS` não adiciona colunas a tabela existente, só cria se ausente.** **(3) `eventstore.Load` deve RESTAURAR sem disparar hook de persistência nem subscriber (senão re-grava/república o que já existe) e deve recalcular o `seq` pelo máximo carregado (senão o próximo Append colide na sequência).** **(4) `POST /run` + SSE fecha o "scriptável": o cliente dispara via HTTP e observa via stream — sem precisar de GUI. É o que separa um laboratório de um SISTEMA.** **(5) `lastRun` compartilhado entre runs concorrentes é data race — um `runMu` serializa; o custo é mínimo (runs são raros).** **(6) O `systemd-run --user` resolve a instabilidade do daemon que o `setsid`/`nohup`/`disown` NÃO resolvem de forma confiável (a shell tool mata o process group quando o comando estoura o timeout) — serviço systemd é a resposta enterprise, não gambiarra de detach.** **(7) Extrair lógica de `cmd/*` para `internal/*` é o que permite reusar (o cmd/evolve virou cliente fino do internal/evolve) — mesma lição do L195 (não duplicar).** |
