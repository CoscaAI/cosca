# L345 — Campanha FASE 3: curva do V-Cache (o joelho)

## Experimento
Benchmark NOVO (vcache_curve_test.go, BenchmarkVCacheCurve_N): generation
sintetico minimo (so slabs do score8 — sem float32), dim 768, 16 workers,
benchtime 1s/run, 3 iteracoes de aquecimento (paginas quentes, L340).
Tamanhos: 10k..1M (slab 7.3MB..732MB).

## Resultado (curva limpa e monotonica)
Regime L3 pleno:   <= ~100k (73MB)  -> 85 GB/s, ~110 Mvec/s
Transicao (LRU):   ~120k-200k       -> 78 -> 62 GB/s (cache parcial)
Regime RAM:        >= ~250k         -> 40-45 GB/s (teto DDR4)
1M sintetico = 52.5 Mvec/s (oraculo real 48.63 — consistente, overhead do
indice real); 100k sintetico = 110.7 vs real 80.82 (overhead do indice real:
slab float32 presente + materializacao).

## Licoes
1. benchtime 5x em runs curtos (<1ms) = RUIDO (10k deu 49 GB/s erratico);
   benchtime=1s por run estabilizou a curva. Medicao de cache precisa de
   tempo, nao de iteracoes fixas.
2. O joelho NAO e um degrau: o L3 96MB vaza GRADUALMENTE (LRU) entre
   120k-200k (88-147MB). cache_budget conservador = 80MB (15% de margem).
3. Overhead fixo domina slabs pequenos: 10k = 66.7 Mvec/s (setup/merge de 16
   workers pesa em scans de ~150us).

## DECISION (epistemologia FACT->MEASURED->DECISION)
FACT L3 nominal = 96MB; MEASURED regime pleno ate ~100k (73MB); DECISION
cache_budget = 80MB -> RegimeL3 abaixo (producao hoje 13.8k = 10.6MB ✓,
62k re-embed = 48MB ainda L3 ✓); RegimeRAM acima.
