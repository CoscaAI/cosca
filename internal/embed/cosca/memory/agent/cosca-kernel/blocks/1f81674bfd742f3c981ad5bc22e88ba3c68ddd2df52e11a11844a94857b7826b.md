# L339 — Assembly VEX no Go: o mapa real do plan9 (kernel int8 AVX2)

## Contexto
Don pediu: passar de 14M vec/s na busca vetorial usando toda a RAM e CPU.
Baseline float32 (L311): 12.07 Mvec/s (37 GB/s — teto de bandwidth DDR4).
Probe int8 em Go puro: PIOR (10.34M) — o compilador Go não emite SIMD.
Solução: kernel AVX2 em assembly (dot8_amd64.s) — 30M x 768 int8 = 23GB,
16 workers. RESULTADO: 15.21 Mvec/s (11.68 GB/s reais, 46.74 GB/s equiv-float32).
OBJETIVO CUMPRIDO: passou de 14M com 4x menos bandwidth por vetor.

## A descoberta: ordem dos operandos no go assembler 1.26.5 (VEX)
O plan9 do Go NÃO é nem Intel nem AT&T puro. Mapeamento real (validado por
execução, não só por bytes):
- 2-op (VPMOVZXBW, VPMOVSXBW, VMOVDQU load): escrever (src, dst).
  1o slot -> modrm.rm (fonte), 2o -> modrm.reg (destino).
  Ex.: "VPMOVZXBW X1, X5" executa X5 <- zx(X1).
- 3-op (VPMADDWD, VPADDD): escrever (src2, src1, dst).
  1o -> modrm.rm (src2), 2o -> vvvv (src1), 3o -> modrm.reg (DESTINO!).
  Ex.: "VPMADDWD X1, X5, X5" executa X5 <- X5*X1.
- VPSHUFD: (imm, src, dst). VMOVD XMM->GPR: (XMM, GPR) (XMM vai no reg).
- "VPMADDUBSW Y3, Y1, Y2" (estilo dst,src1,src2 Intel) codifica modrm.reg
  ERRADO para certas combinacoes (ex.: reg=Y5 em vez de Y2) — bug do assembler,
  sem padrão identificado: EVITAR.

## Outros bugs e armadilhas do go assembler 1.26.5
- "unexpected EOF" no fim do .s = arquivo sem newline final (Write tool grava
  sem \n; `echo "" >>` corrige). Unicode em comentarios tambem quebra.
- go tool objdump decodifica AVX2 ERRADO (mostra OUTL/ROLL/CMC): usar
  `go tool asm -o x.o` + `od -A x -t x1` + decodificacao manual.
- VEX byte2 = ~R ~X ~B: bit7=1 significa R=0 (sem extensao). Fui enganado
  por decodificar ao contrario.
- <ABIInternal> no TEXT so no pacote runtime; em pacote normal: ABI0 com
  args na stack (caller gera wrapper — funciona, validado com minAddOne).
- VPMOVZXBW/SXBW: so XMM (nao YMM) e so reg-reg (memoria rejeitada: ytab
  _yvcvtdq2pd nao cobre). YMM8+ tambem bugado.
- Build tags //go:build antes de package.

## Aritmetica do kernel (bias)
qb[i]=q[i]+128 (uint8 unsigned) x rb[i]=r[i] (int8 signed):
dot(q,r) = Soma(qb*rb) - 128*Soma(r). vpmaddubsw nao satura para i8xi8
(127*127=16129<32767). Correcao no chamador: 1 mul + 1 sub por row.
Kernel: 16 elems/iter, X0 acumulador, X1-X6, 19 inst/16 elems.
