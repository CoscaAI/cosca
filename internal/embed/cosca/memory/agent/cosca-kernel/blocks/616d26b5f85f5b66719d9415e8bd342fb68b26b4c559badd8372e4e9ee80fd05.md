## O que entrou
RECOVERY_PROTOCOL.md (internal/embed/cosca/): o mecanismo formal para sair
de estados nao compreendidos.
- Invariante central: LAST COMMIT != LAST VALID COMMIT != LAST KNOWN-GOOD.
- Lema: "nao restaure aquilo que voce ainda nao entende".
- Espinha dorsal: DETECTAR -> QUESTIONAR -> PROVAR -> CORRIGIR -> RECUPERAR
  -> EXPLICAR.
- Mapa de camadas (fonte de verdade / derivado / identidade / operacional)
  com o recovery de cada uma.
- 9 fases: DETECTAR (sinais: doctor, verify, chain, comportamento) ->
  QUESTIONAR (interrogatorio L377) -> IDENTIFICAR (ultimo estado bom) ->
  AVALIAR (comprometimento por camada) -> DECIDIR (seguro? UNKNOWN ->
  parar) -> RECONSTRUIR (identidade verificada) -> PROVAR (L375/F6) ->
  PRESERVAR (congelar) -> PARAR (autorizacao humana).
- Regras de ouro: o erro nao destroi a historia; recovery != rollback
  cego; cada camada tem seu recovery; o rastro; preservar o valido.
