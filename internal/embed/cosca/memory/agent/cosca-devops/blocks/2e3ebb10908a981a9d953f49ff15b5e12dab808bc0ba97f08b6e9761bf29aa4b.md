| **Learned** | (1) Go does NOT expose true branch coverage via CLI tooling — `go tool cover -func` reports statement coverage only. (2) The `coverage.out` file (generated by `-covermode=atomic`) contains per-basic-block execution counts — each line is a block with `numStmts` and `count` fields. (3) Branch coverage can be approximated as: `(blocks with count > 0) / (total blocks) * 100`. This works because conditional branches create new basic blocks in Go's coverage model. (4) Threshold set at 60% (lower than 70% statement coverage) because branches (error paths, edge cases) are inherently harder to cover. (5) For true branch coverage, third-party tools like `gocov` or `go-test-coverage` would be needed. |
| **Next** | Consider integrating gocov or go-test-coverage for richer multi-metric coverage reports. |
