O que o torna diferente

1. Não é um chatbot — é uma organização

O Cosca implementa uma hierarquia operacional: Don → Kernel → CEO → CTO → Chiefs → Specialists. O Kernel roteia e nunca implementa — delega a agentes com papel definido, como uma empresa real. Cada agente tem domínio, capacidades e responsabilidades.

2. Busca por entendimento, não por palavra

Usa busca híbrida: FTS5 (BM25) + similaridade vetorial (cosseno, embeddings locais 768-dim) + grafo de conhecimento. Entende o significado — uma query "proteção da casa" retorna conteúdo sobre segurança/família, mesmo sem as palavras iguais.

3. Conhecimento com proveniência

Todo conhecimento é classificado (FATO / EVIDÊNCIA / INFERÊNCIA) e rastreável. "Zero achismo" — sem evidência, é hipótese, marcada como tal. A busca não inventa o que não existe.

4. Memória que evolui e se cura

O kernel aprende com cada sessão (auto-evolução). A memória é curada — aprendizado obsoleto vira superseded, erros são registrados em failures.md. Memória > Velocidade.

5. Integridade criptográfica

Uma family chain assinada (Ed25519 + DPAPI machine-bound) protege a identidade. Se o histórico é alterado, o sistema bloqueia o boot (fail-closed). Sandbox + JWT autenticação em camadas.

Segurança & Governança

  • Family chain Ed25519 + DPAPI — machine-bound, testemunho de imutabilidade
  • Fail-closed em cada camada — na dúvida, tranca
  • JWT com anti-enumeração + rotação de tokens
  • Sandbox (bwrap Linux/WSL2) + loopback-only REST
  • Sistema de níveis de soberania (L1/L2/L3) com watchdog auto-descida
  • Constituição — 8 princípios imutáveis + garantias do Don

Arquitetura de dados (ADR-013)

Não usa banco monolítico. Dados particionados em módulos físicos < 100 MB (Core/Grafo/Projects/Vetores), cada um coeso. O índice vetorial é regenerável — nunca fonte.
