# COSCA Terminal v2 — Princípio de Design

> **"Use o OpenCode como benchmark de UX, não como arquitetura de produto."**

---

## Regra de Ouro

Se uma decisão de UI entrar em conflito entre **"parecer OpenCode"** e **"expor uma capacidade nativa do COSCA"**, priorize a **capacidade do COSCA**, mantendo a **ergonomia do OpenCode**.

## O que preservar (OpenCode = benchmark de UX)

- Terminal-first
- Conversa com agente como centro
- Sessões/workspaces
- Navegação rápida por teclado
- Command palette
- Atalhos
- Diff e edição
- Execução de comandos
- Tool calls visíveis
- Tarefas/progresso
- Git
- Contexto do trabalho
- Layout denso, profissional e rápido
- Pouca UI ornamental
- Fluxo contínuo: conversar → agente agir → revisar → continuar

## O que o COSCA vai além (capacidades nativas)

- Agent Orchestration (Don/Kernel/Chiefs/Specialists)
- Memory Explorer (WHY DOES COSCA BELIEVE THIS?)
- Context Inspector (o que entrou no contexto e por quê)
- Knowledge/Graph
- Permission Center (allow/ask/deny/approval)
- Computer Mode / Fabric Computer (capability + permission)
- Mission Control (cockpit do sistema)
- Verification Mode (prova, não promessa)
- Observabilidade da execução

## Alvo

**OpenCode na ergonomia + COSCA no cérebro + Fabric Computer nas capacidades + identidade visual própria.**
